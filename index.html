How sure is it, and why?

A system with no neural weights. Every answer — a fact or a program — carries a measured confidence, the evidence behind it, and an honest refusal when it doesn't have enough.

How the number is computed

Count how many independent sources assert the fact. That count maps to a probability through a curve fitted against a held-out source the system never consults when answering.

Fitted on one half of the entities and tested on the other, split by subject so no entity appears on both sides. Expected calibration error: 0.20 percentage points across 496,464 held-out facts. The curve predicts — it is not describing its own training data.

The law

An anchor is a second source, not a second opinion. One source is close to a coin flip. A second independently collected source takes it to 87%. That lift survives controls for popularity, for shared lineage between sources, and for gaps in the reference set.

What this is. The whole graph — 66,404,117 facts over 12.2 million subjects — sharded so your browser fetches only the piece it needs. It is a lookup over recorded relations, not a chatbot: it reports what sources asserted, and when nothing asserts anything it says so instead of inventing.

Two limits, stated rather than hidden. (1) Subjects are matched by surface text, not a disambiguated entity id, so a name shared by more than one real thing (many towns are named "Berlin") can appear merged under one heading. Every fact shown is still real and independently sourced — it may just belong to more than one thing with that name. (2) There is no per-subject cap: every one of the 66,404,117 facts is here, and a well-documented subject keeps all of its edges (Australia carries 975). An earlier build capped each subject at 80 facts and, by doing so, silently deleted Australia → capital  → Canberra — the answer to this page's own headline example. Measuring the cap rather than defending it is what removed it: it was discarding 1.58% of the graph, and 99.9% of subjects never came near it. "Not recorded here" now genuinely means the sources did not record it.

A lookup answers one hop. This chains them: the capital of the country Melbourne is in is not a recorded fact — it is Melbourne → country → Australia → capital → Canberra, a path the engine has to find. Watch it walk the graph, and watch the confidence compound.

Why this is not a lookup

No source recorded “Melbourne → capital of its country → Canberra.” The engine finds it by searching outward from the subject, hop by hop, fetching each new shard only when it needs it — and every edge it walks is a real fact with real sources, so the chain is auditable end to end.

The confidence is composed, not asserted: the chain probability is the product of each hop's own measured probability. Two 87% hops give 76% — chaining costs certainty, and the engine reports that cost instead of hiding it.

The assumption, stated. Multiplying hop probabilities treats the hops as independent. That is an assumption, not a measurement — the single-hop numbers on the first tab are measured against held-out data, this composition on top of them is not. It is labelled that way everywhere it appears, because a number you can't source is exactly what this whole project is arguing against.

What is hand-written here, and what isn't

An honest demo has to say where the human help is. Hand-written: a fixed table of about fifteen question-word aliases, so “who founded X” reaches the founded by relation and “how tall” reaches height. It is a listed, auditable mapping in the page source — not learned, and not per-question. Not hand-written: the chains, the answers, the confidences, and the ranking. Nothing about any specific subject is special-cased, and no answer is stored anywhere. Type a subject nobody would put in a demo and it does the same work.

The bounds are real too: at most 8 branches per hop, 4 hops deep, 26 shard fetches per question. When a bound stops the search the trace says which one and what was left unopened, because a bounded search reported as a settled absence is the exact failure this project argues against.

Failure is a result

When a chain dead-ends, the engine names the exact node it could not get out of rather than inventing a plausible ending. A broken chain that says where it broke is more useful than a complete-looking chain that is quietly wrong.

The other half of the same idea, in a different domain: given input→output examples, search a fixed set of primitives for one that satisfies every example — verified by real execution, not predicted by a model. This box re-implements a small slice of it entirely in this page; the measured system is a ~2,600-line search engine tested against 224 MBPP+ programming tasks.

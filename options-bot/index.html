Options trader bot

A SPY 0DTE opening-range breakout bot for Interactive Brokers. It began as a script that arrived cut off mid-line. It is now finished, checked against a written spec with the light loop, and tested through simulated trading days.

Download the bot (zip) Read the code README
  • Signals onlySends no order until you set its stop and target. Until then it shows each trade it would make.
  • Paper firstRefuses a live port or a live account unless you add --live.
  • Exits held at IBThe stop and target sit at Interactive Brokers as one OCA pair, so they keep working if the PC or the script dies.
  • Never left openSells what it bought 10 minutes before the close (earlier on half days), and on Ctrl+C.

Run it on a paper account

  1. Start TWS or IB Gateway logged in to the paper account, with the API on port 7497 (TWS: Global Configuration, API, Settings, "Enable ActiveX and Socket Clients").
  2. The account needs live market data for SPY and for US options (OPRA). Without it the bot stops at startup and says so.
  3. pip install -r requirements.txt (it uses ib_async 2.1.0).
  4. python zdt_autopilot.py

To let it trade, set STOP_LOSS_PCT and TAKE_PROFIT_PCT near the top of the file. The original script stops before its exit rules, so the bot does not guess them.

What it does

  1. Connects and says PAPER or LIVE with the account ID.
  2. Reads the account's USD cash balance, and stops if IB does not report one.
  3. Reads today's session hours from IB, waits for the first 15-minute bar to close, and takes its high and low as the opening range.
  4. Streams SPY's last price every second.
  5. Signals a CALL when SPY trades more than $0.30 above the range, a PUT when it trades more than $0.30 below.
  6. Picks today's expiry and the listed out-of-the-money strike nearest spot +/- $1.50.
  7. Sizes the order from the original's tier table, never more than the balance covers.
  8. Buys with a limit at the ask and waits for the fill. After 10 seconds the unfilled part is cancelled.
  9. Places the stop and the target at IB as one OCA pair.
  10. Waits for one of them to fill, or sells at market at the flatten time.
  11. Writes one row to trade_execution_log.csv, with the net after the commissions IB reports.
  12. Waits for SPY to come back inside the range before it takes another signal, and stops for the day after two losses in a row.
  13. Cancels its own orders, sells what it bought, and disconnects.

Each step and every alternate path (holidays, delayed data, a missing expiry, an unaffordable contract, a dropped connection) is written out in the README, and each has a test.

Fixed from the original

  • It bought one contract even when one cost more than the balance. It now does not trade.
  • Its opening range was the first bar of the last 30 minutes, which is the opening bar only between about 9:45 and 10:15. Started at 9:35 it was a bar still forming; started at 11:00 it was the 10:30 bar.
  • When the balance could not be read it carried on with $100 as if that were real.
  • When today's expiry was missing it switched to the next one, which is not a 0DTE trade.
  • It crashed when no strike was within $5 of its target, and never checked that IB knew the contract it picked.
  • It took the date from the PC's clock in the PC's own time zone, not New York time.

Checked with the light loop

The light loop checks code against a written spec. Every rule quotes the spec word for word, and a fault counts only when a small program run on the code proves it. The spec here, SPEC.md, has three parts: the use case, the original script's own comments, and the ib_async library's documentation.

The tests run whole simulated trading days against an in-memory TWS (fake_ib_async.py), so no test can reach TWS or an account. One more test reads the real ib_async 2.1.0 source and checks that every call, keyword and field the bot uses exists there.

What the tests cannot show: how Interactive Brokers itself fills, prices and reports on a real day. The first paper run is that check.

Open questions before it trades

  1. The original ends at the PUT check. Is there more of it?
  2. What stop and target should it use?
  3. What does TIME_STOP_PCT = 0.25 do? The original sets it but uses it after the point where it ends.
  4. After a trade, should it trade again the same day? It now waits for SPY to come back inside the range, then takes the next breakout, until two losses in a row.
  5. Size from the whole account, or never from more than a set budget? A paper account usually holds far more than $100.
  6. The original aims at about 0.20 delta with a fixed $1.50 offset, which is a different delta at 9:45 than at 15:00. Keep the offset, or pick by the delta IB reports?

Software, not financial advice. Options can lose their whole premium, and 0DTE options expire the same day. Run it on a paper account first.

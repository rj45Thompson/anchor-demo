Back to 1999: requirements first

This is how we review our code: we pour the effort into requirements first. It is time to learn systems analysis and design again. Agile is, for the most part, dead. Long live waterfall.

The reason is mechanical. The more requirements you have, the better a graph neural network (GNN) works at filling the gaps, and the more of the loop closes, so that nothing is left to a guess. That is what gets you slopless code. We want hand-crafted quality on an IKEA budget.

Where this comes from

Measured On the shop feature, the graph neural network (GNN) scored 0.48 with a tenth of the requirement links, 0.63 with a quarter, 0.73 with half and 0.77 with three quarters or all, against 0.67 for a plain rule with no test results to read. See seed it first. Once test results exist, a plain rule that reads them does better on that feature: see the part that learns.

It extracts new requirements from the ones you have

The tool automatically extracts requirements from existing requirements. You do not list them by hand. It walks each use case step by step: every step needs something to be true, and when no requirement provides that, the chain has inferred one nobody wrote. It is marked inferred and goes to the owner as a question, because only the owner can decide it. See the idea in one minute for what that found on the shop feature, and growing a model from a small seed for how far it went from 3 requirements.

Complete in, accurate out

The more complete the requirements, the more accurate the prompt built from them: an agent acting on them has less to guess. Which ones you write first matters as well, so start with the ones that run through the most code (seed it first).

Remix, don't invent

When adding a large feature, it is probably better to remix two features that already have solid requirements than to invent something new with no clear ones. Adding a weapon shop, say, is a remix of a shop and an inventory, and a shop is one of the examples this tool was built on. A remix starts from requirements that have already been tested, so the gaps it leaves are the places where the two meet, and the walk finds those. A new invention starts with nothing to walk.

Open This is our judgment from building with it. No run has measured complete against incomplete requirements, or remix against invention, directly.

How it works

  1. Write it, break it

    You write the requirements as a model, and the harness breaks every decision in the code every way it knows, in one compile; each break must fail a test.

  2. One graph

    Every requirement, step, method, branch, break and test becomes a node in one graph, and that is the graph flying above, drawn with its names removed.

  3. Checked reasoning

    Claude writes its reasoning as a chain of steps, each citing what it stands on, and a citation that is not there fails the run.

  4. A proposer

    A graph neural network proposes which requirement owns new code, as a question and never a verdict, and it has to beat plain rules.

  5. Self-improving

    Self-improvement is on by default: every pass records its own stats, checks them against its own rules and names what to improve next.

What it costs, and its limits

Costs

  • 1.2 to 2.3 times the tokens, 3 to 55 times the time, on small tasks.
  • 24 minutes for a full pass of 1,097 breaks.

Limits

  • Prototype 0.1.
  • A green result on a thin model means little.
  • 95% accuracy on code is a target, not a measurement.
  • On Unreal's SemVer.cs the C# adapter saw 35 of 68 statements, and its report did not say so. Fixed, with planted tests.

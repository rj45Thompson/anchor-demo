The node graph, and flying through it

Everything the loop knows about a feature is one graph: who asked for what, which code does it, every way that code was broken, and which test noticed. The shop feature's graph has 1,714 nodes and 10,024 edges. It is stored as SQLite and N-Triples. The fly-through demo draws that store as it is, with nothing added and nothing left out. The pictures behind the slides are stills from the same page.

How it is laid out

The store has no shape of its own, so the demo gives it one you can read from top to bottom, one ring for each kind of node:

  • Why it exists: 19 sources, 27 requirements (17 written by people, 10 inferred by walking the use cases), 7 owner's questions, 6 use cases and their 32 steps.
  • Claude's reasoning: a chain and its 9 steps, each citing what it stands on.
  • What the code does: 50 methods in a ring, sorted by name, so a class's methods sit together.
  • What proves it: 313 branches, 1,097 breaks and 45 tests. Each branch and each break sits at the angle of the method it belongs to, so a method and everything under it line up.

How code maps to requirements

Two kinds of edge do it. A branch maps to a requirement: 620 of those. A branch is at a method: 313. Together they take you from any decision in the code to who asked for it, and from a requirement to all the code that answers to it. A decision no requirement owns is a hole, and the loop lists it.

What the red points are

The 130 breaks no test caught. Red is what the graph records, not a verdict: 23 of them are proven by compiled code to be the same program, 20 have a written reason, 52 have no verdict yet, and 35 are unexplained, which are the real work. That is what the deck's 96.5% means: 967 caught against those 35, leaving out the other 95. Excusing only the 23 that are proven, it is 90.0%, 967 of 1,074.

The demo

Drag to orbit, scroll to zoom, W A S D to fly, Q and E for down and up. The tour follows one real thread: a source, a requirement, the step that needs it, Claude's reasoning, the code, a branch, a break of that branch, the test that caught it, and a break that got past. The Show menu narrows it to one question: how code maps to requirements, every break and what caught it, Claude's reasoning, requirements and use cases, or what the graph neural network reads.

It is a tool in the kit, for any graph the loop has written. --hide keeps names you choose off the page:

python graph_flythrough.py <store.sqlite> --out page.html --hide "NameA|NameB"

The knowledge graph

A graph here is just a list of things (nodes) and the links between them (edges). The things are requirements, use case steps, places in the code, branches, breaks, tests and reasoning steps. The links say how they relate, for example:

requirement W-1   is checked by   test Pay_TakesExactlyThePrice
break #312        was caught by   test Pay_TakesExactlyThePrice
method Pay        is claimed by   requirement W-1

The graph is the record: the 17 checks read it, and a later agent reads it instead of re-deriving what an earlier one found. It is written on every run as a SQLite database and as an N-Triples text file, a standard format any graph tool can open.

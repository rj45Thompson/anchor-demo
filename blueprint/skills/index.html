Blueprint view prototype

The skills behind the loop

The Blueprint view prototype was built in under 24 hours, on top of RJ’s existing u2ue toolkit, by AI agents directed by RJ. These five skills set how the agents worked. Each skill is a plain-text playbook an agent loads before it starts; open one to read it in full.

  • /usecase-map

    Builds a use case model from the problem story and a class model from the code, and never lets the two blur.

    In the prototype: built the use case model from RJ’s Blueprint Paradox discussion and his messages: 59 use cases at three levels and 230 requirements, with the class model held to the code.

  • /usecase-interrogate

    Walks the use case chain and turns every hole into a question. The gate stays red while any question is open.

    In the prototype: the gap checker behind closed loop requirements. Every pathway and closed space is counted; requirements the chain needs but nobody wrote become questions for the owner (18 on the Lock-On Blueprint), and a logged reasoning chain is held to the graph.

    Read the skill
    Loading…

  • /morph

    Zwicky’s morphological box: every dimension and value of an option space, each marked present (with where) or absent (with why).

    In the prototype: laid out the view’s option space (direction, what is graphed, renderer, fidelity, layout, edit route, live data, replay, AI input) and Unreal’s 19 Blueprint-editor panels: 11 present, 8 absent, each with where or why.

    Read the skill
    Loading…

  • /decide

    Routes a judgement call through a calibrated decision matrix, so the agent takes a measured strategy instead of guessing.

    In the prototype: settled the opening forks: a Blueprint-styled view over code rather than real Blueprint assets, a web page before an Unreal plugin, headless replays rather than live editor data. It also picked the knowledge-graph store by benchmark (SQLite).

    Read the skill
    Loading…

  • /autonomous-worker

    Keeps a task list on disk and works it item by item until done, checking each item against something a stranger could re-check.

    In the prototype: ran the work off the experiment’s TASKS.md. Every item had a “done when” check, verified before it was ticked; blockers were recorded with their measurement.

The use case checkers these skills drive are open source with the prototype, under the MIT licence, at github.com/rj45Thompson/blueprint-view-source:

usecase_model.py (the requirements “compiler”), usecase_kg.py (the knowledge graph and the closed-loop gate), interrogate.py, coverage.py and the Blueprint view itself. The rest, such as morph_box.py and uml.py, live in RJ’s private toolkit repository, available on request.

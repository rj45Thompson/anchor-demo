Blueprint View

Game code drawn as Blueprint-style graphs to make it easier to understand, and Unreal Blueprints turned back into code, with requirements built from human friction first. It never writes the game, and it joins u2ue only if a measured report makes the case for it.

This review is the experiment as it stood early on 10-28. The online sample with its closed loop, the Pong hello world, the asteroid shooter (a whole game, playing on its converted Blueprint) and the city came after it, and are on the showcase and the city above.

Viability
Built and measured for right answers. Not yet measured with people.

Phases 1 to 7 and 9a are built, and a converter from Blueprint to code was added as a new requirement mid-run: read any method as a graph in five forms, find it, follow its calls, replay a battle and scrub it to the step a planted fault appears, set a value on a wire with no rebuild, change the sandbox through gates, and read real Unreal Blueprints as code. Every answer the experiment gives was held to a key computed another way. What it has not been measured for is friction: no person has used it, and that needs named testers and a baseline (IR-12).

Not real Blueprint assets

A Blueprint call node binds a UFunction (K2Node_CallFunction.h lines 77 and 158), and the model is plain C#. IR-3 asks for that to be confirmed.

Not live edits in a running editor

Hot reloading stays Off in the Unreal project in use, so a write never recompiles under an open editor. The same idea runs on a deterministic replay: a valve on a wire, a re-run in seconds, the new outcome beside the old.

Never a write to the game

Every change lands in a sandbox copy that records its game commit (cc93149), and every run that writes is wrapped by an audit hashing the game's folders: 22 of 22 audit records say 0 changes. The engine and the second game are only ever read, from copies.

Requirements first (REQ-BPV-27, UC-BV34, BC-1 to BC-10 from the engine's 113 node classes), then the code, tested only on text the engine itself wrote: eleven Unreal 5.7.1 templates copied and exported by a headless commandlet with no window.

What the code means is read from the engine, not assumed: a function's outputs are out parameters and a pure node runs once per step (KismetCompiler.cpp); unset pins print what the compiler writes; ForEachLoop, ForLoop, WhileLoop, FlipFlop and DoOnce follow their own macro graphs, exported from the engine and read. The page has a From Blueprint tab: paste nodes, read them in every form. Not yet tried: a real clipboard copy, which only the editor makes.

One graph, many forms

The design rule: the graph is stored in the node graph's own pseudo-language, and every view is generated from it. A reader picks Blueprint style, another visual style or C# text, and other code languages can follow. The stored form is trusted only while every graph prints back to its method's text.

flowchart LR
  G["Game code, read only"] --> R["Reader: census vocabulary, 59 node families"]
  R --> P[("Stored graph in its own pseudo-language")]
  P --> B["Blueprint style"]
  P --> V["Another visual style"]
  P --> T["C# text"]

Open product decisions

Sixteen requirements the chain needs and nobody has stated, asked at the 35 places they are cited. Each pathway that rests on one says what the view does until it is decided. These eleven are product calls.

IR-1

Which code is drawn first: the engine-free model and presentation, the Unreal host classes, or the Unity scripts? Until then, engine-bound code is drawn without live data and marked.

IR-2

Where does the view live first: a browser page or the Unreal editor?

IR-3

Confirm a Blueprint-styled view the toolkit owns rather than real Blueprint assets. Until then, a request for a real asset is explained and offered the styled view.

IR-4

Which way does execution flow: down the page like text, or left to right like Blueprint?

IR-5

What does the overview map show: modules and classes with calls, the battle flow, or both? Until then, modules and classes with calls.

IR-6

How fast must "instantly" be for a value change on a replay?

IR-7

Which edits does the graph itself support, and which go to a spoken or typed command instead?

IR-8

Which AI writes code from a command, where does it run, and who pays for it in the product?

IR-9

What counts as a bottleneck: time per node against which budget?

IR-14

Which second visual system, and which code languages beyond C#?

IR-15

Does the preview of a valve's effect need the game's own picture? That needs the Unreal port playing the replay in an instance of its own.

The other five hold a stated default until decided otherwise. IR-10: every change acts on the sandbox. IR-11: the sandbox records its game commit and lists kept changes before a refresh. IR-12: rounds without named testers are run by Claude and marked not human. IR-13: notes are kept per person. IR-16: results are kept in the experiment folder with their date, snapshot and tool version.

Three more from the build, each measured:

DR-1

The graphs draw 2.5 nodes per statement where the requirement aimed at 1.5. Fold more into a node (a condition as one box), or accept 2.5? Failed, left as it is.

LY-6

A big graph opens with every node shown; the requirement asked for at most 30 visible. Build fold and focus? Failed, not built.

BC5

One Ctrl+C in an Unreal editor: any Blueprint nodes copied and pasted into the page's From Blueprint tab, so the converter meets a real clipboard copy. Only the editor writes one.
